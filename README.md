# 幸福小岛 · 婚礼邀请函

动物森友会风格的手机婚礼邀请页面，包含气球礼物开场、小岛广播、渡渡鸟航空登机牌、乘机动画、婚礼日历、祝福互动和回执。已放入 11 张婚纱照，按横竖比例分布在登岛、广播、仪式、相册和结尾；相册包含 4 张中式喜服照，未使用的照片位置自动隐藏。

## 预览与配置

公开页面只提供邀请函、祝福互动和回执，没有婚礼资料编辑、上传或导出入口，`?edit=1` 也不会开启编辑功能。新人姓名、日期、地址、联系方式和照片路径统一在 `config.js` 中维护；旧浏览器草稿不再读取。

双击 `婚礼邀请函.html` 可以离线预览。修改源码后，运行 `python3 scripts/build-standalone.py` 同步单文件。祝福历史功能需要联网访问 Node 服务。

## 部署

在 `server/` 目录运行 `npm ci`、`npm start`，默认访问 <http://localhost:3000/>。该服务同时提供邀请函及 Redis 数据接口。纯静态托管仅支持邀请函浏览，不能直接连接 Redis。

服务端 `server/.env` 保存本地 Redis 配置，启动时自动读取；文件被 Git 忽略，不会进入前端或离线文件。其他环境配置 `UPSTASH_REDIS_REST_URL`、`UPSTASH_REDIS_REST_TOKEN`，参考 [server/.env.example](server/.env.example)。启动与部署配置见 [服务说明](server/README.md)。

服务器、现有 Docker Compose 服务和 `/wedding/` 路由说明见 [线上部署](DEPLOYMENT.md)。

## 功能说明

- 旅程按「拆礼物 → 登岛安排 → 听完广播 → 领取机票 → 飞行抵达 → 婚礼广场 → 相册 → 日程 → 回执」逐步解锁。导航和网址锚点不能越过未完成章节；已解锁的内容可随时回看。刷新后重新开始旅程。
- 通过 Node 服务部署并配置 Redis 后，首页显示全站访问次数、访客数与祝福数。访客以浏览器 Cookie 区分，同一访客仅计一份祝福；清除 Cookie 或更换浏览器会视为新访客。Redis 不可用时显示未连接，重试成功后再确认祝福。
- 页面打开时从 Redis 读取最近 50 条真实祝福，并在首页和结尾的独立区域滚动显示。可暂停；减少动态效果设置下静态展示；展开「查看祝福文字」可阅读完整留言。没有历史文字时显示空状态，不编造留言。
- 访客可在首页或结尾填写昵称和祝福。每个浏览器保存一条公开留言；曾只点过祝福的旧访客可补写文字，原计数保留。昵称与文字会公开展示。
- 离线或服务不可用时可继续浏览旅程，无法同步历史祝福。
- 在回执中填写的祝福与独立「写句祝福」入口共用 Redis 保存流程。文字保存成功后才显示回执；保存失败保留填写内容并提示重试。空白祝福的默认文案不会发布；已送达的公开祝福不会被修改回执覆盖。赴约信息仍需复制回执通过微信发给新人。
- 打开页面时保持静音；点击礼物或音乐按钮后尝试播放背景音乐。
- 打开导航或切换应用会暂停音乐，返回时续播此前开启的音乐；主动关闭后保持静音。若浏览器拦截自动续播，下次点击页面或音乐按钮会重试。
- 开场即请求全部婚纱照、场景图和票券背景，不等待滚动到后续章节；图片异步解码且同时最多解码 3 张。图片失败不会阻塞浏览。图片等静态素材缓存一天，页面、配置和脚本每次重新校验，以便及时收到更新。
- 游戏字体采用简体圆体替代，可在配置文件指定自定义字体；未验证为动森港版原字库。
- 微信自定义分享卡片需要额外的公众号 JS-SDK 和服务端签名接入。
